topic: Verbosia Translation Memory V2 hardening
updated: 2026-08-27T23:10
---

- (direction) Harden Translation Memory before the v0.1 release using the confirmed audit reproductions: delimiter collision, glossary/do-not-translate partition collision, missing semantic dimensions, and empty model acceptance.
- (decision) Use stable spec slug translation-memory-v2 and derive one technical companion, key-contract-and-migration.md, containing the canonical identity, compatibility policy, operational behavior, and golden vectors.
- (capability) CAP-1 — intent: The translation engine can address every translation by a collision-resistant, explicitly versioned identity. success: distinct semantic inputs, including adversarial NUL and delimiter values, never produce the same key in the required vectors, while identical inputs remain deterministic across runs and platforms.
- (capability) CAP-2 — intent: A cache lookup reflects the complete translation request that can affect provider output. success: source language, target language, target variant, actual provider, model, tone, ordered glossary, ordered do-not-translate list, prompt version, and exact source text each participate in identity and each single-field mutation produces a miss.
- (capability) CAP-3 — intent: Operators can adopt TM v2 without unsafe reuse or silent deletion of legacy entries. success: v1 entries are never read, backfilled, or synchronized as v2; existing local data can coexist until explicit dry-run-aware cleanup, and Redis v2 keys occupy a disjoint namespace.
- (capability) CAP-4 — intent: Translation, human review, pruning, synchronization, and all cache tiers use one consistent TM v2 contract. success: every producer and consumer derives the same key, review edits survive reruns, pruning recognizes live v2 source digests without deleting entries merely because provider/model context differs, and sync excludes legacy keys.
- (capability) CAP-5 — intent: Developers and operators can audit and reproduce the TM identity contract. success: exported types/functions, docs, deterministic golden vectors, package runtime exports, and focused integration tests agree on the same v2 format and migration behavior.
- (constraint) The canonical v2 key format is v2:<contextDigestHex>:<sourceDigestHex>, where both digests are lowercase full SHA-256 and the context preimage is RFC 8785/JCS with an explicit Verbosia TM v2 domain/version.
- (constraint) The context preimage contains exact resolved values for sourceLang, targetLang, targetVariant or null, actual provider name, non-empty model, tone or null, ordered glossary, ordered doNotTranslate, and non-empty promptVersion; sourceDigest hashes the exact UTF-8 sourceText separately.
- (constraint) Arrays remain ordered and partitioned because the current provider prompt and DeepL protection pipeline observe both membership class and order; no sorting, merging, trimming, deduplication, delimiter joining, or Unicode normalization may create equivalence absent from the actual request.
- (constraint) Translation configuration rejects an empty or whitespace-only model before discovery, cache lookup, or provider execution; required identity fields fail closed rather than falling back to a partial v1-shaped key.
- (constraint) V1 cache entries are untrusted for semantic reuse: no dual-read, key promotion, inferred migration, or provider fallback may turn a v1 hit into v2. Normal translation must not delete legacy data automatically.
- (constraint) Local cleanup of legacy entries is explicit and dry-run-aware; shared Redis legacy keys are ignored rather than globally deleted because ownership cannot be proven.
- (constraint) tm:sync transfers only well-formed v2 keys and reports ignored legacy or malformed keys; prune uses the v2 source digest to preserve live translations across provider/model/context histories and reports legacy cleanup separately.
- (constraint) TM keys and diagnostics must not expose source text, glossary terms, tone, or secrets; cache contents retain only the minimum operational metadata needed for translation, review, synchronization, and maintenance.
- (constraint) The public Core package must export the v2 contract used by internal consumers, and package/tarball verification must prove runtime availability; unsafe v1 behavior is not preserved solely for pre-v0.1 source compatibility.
- (decision) Non-goal: This slice does not change translation quality, prompts, masking, provider retry behavior, content discovery, status hashing, Brand Memory, Evidence Ledger, MCP tools, or SEO/GEO analysis.
- (decision) Non-goal: This slice does not automatically delete Redis v1 data, reconstruct missing v1 semantics, or promise zero provider calls on the first v2 run.
- (assumption) Because Verbosia has not yet passed the v0.1 release gate, safety takes priority over reusing pre-v2 cache entries and one controlled retranslation is acceptable where no v2 entry exists.
- (decision) The success signal is a full translation/review/sync/prune demonstration where adversarial keys remain distinct, semantic changes miss, identical v2 requests hit across tiers, v1 data is ignored without silent deletion, and the complete regression/build/package gate passes.
- (note) Confirmed source evidence absorbed from docs/bugs-2026-08-27.md and current Core code: cache-key.ts delimiter framing collides; glossaryVersion merges partitions after sorting; CacheKeyInput omits sourceLang/provider/variant/tone; config accepts an empty model; review and maintenance independently reconstruct the same incomplete key; Redis prepends a shared tm: namespace.
- (note) Wrapper-only content intentionally dropped: severity labels, unrelated audit findings B2-B35, and narrative about the external reviewer; only load-bearing TM behavior enters this contract.
- (decision) Localized document metadata records tmKeyVersion=2 and the non-sensitive contextDigest used to produce it; human review writes the historical context key from that digest and the current context key when provable, without reconstructing hidden historical fields.
- (constraint) Changing only TM metadata must preserve legacy translatedBy/reviewed behavior and must not expose source text, glossary, tone, provider credentials, or the canonical context preimage.

- (event) Self-validate preservation PASS: every load-bearing confirmed TM audit claim lands in SPEC.md or key-contract-and-migration.md, including delimiter and partition collisions, missing semantic fields, empty model, Redis isolation, legacy handling, review metadata, maintenance behavior, and regression/package gates.
